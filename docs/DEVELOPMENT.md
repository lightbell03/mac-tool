# WheelSpace 개발 노트

사용 방법은 [README](../README.md)를 본다. 이 문서는 동작 규칙·제약·구조·수동 검증표를 모아 둔 개발용 기록이다.


Option 키를 누른 채 마우스 휠을 굴려 macOS의 인접 데스크탑(Space)으로 이동하는 메뉴 막대 앱.
계정·서버·네트워크 연결이 없고, 설정은 이 맥의 UserDefaults(`com.bell.WheelSpace`)에만 저장한다.

| 입력 | 동작 |
| --- | --- |
| Option + 휠 위 | 왼쪽 데스크탑 |
| Option + 휠 아래 | 오른쪽 데스크탑 |
| Option + 휠 왼쪽 / 오른쪽 (설정: 좌우 휠 또는 둘 다) | 왼쪽 / 오른쪽 데스크탑 |
| (Option +) 마우스 뒤로가기 / 앞으로가기 버튼 (설정: 기본 꺼짐) | 왼쪽 / 오른쪽 데스크탑 |
| 보조키 없는 휠, Option + 다른 보조키 + 휠 | 원래 스크롤 그대로 |
| 일시정지·권한 부족·오류 상태 | 모든 스크롤·버튼 그대로 |

휠 방향은 "자연스러운 스크롤" 설정과 관계없이 물리적인 휠 방향 기준이다. 반대가 편하면 설정에서 방향 반전을 켠다(세로·좌우 휠에 함께 적용, 버튼에는 적용 안 함).

## 한영 변환

한영 전환을 놓쳐 잘못 입력한 글자를 클립보드에서 바로잡는다. 번역이 아니라 영문 QWERTY ↔ 두벌식 키 배열만 바꾼다.

**기본: 선택한 글자 바로 바꾸기** (손쉬운 사용 권한 필요)

1. 잘못 입력한 부분을 선택
2. 단축키를 누르고 손을 뗀다
   - ⌃⌥K (Control+Option+K): 영문 → 한글 (`dkssudgktpdy` → `안녕하세요`)
   - ⌃⌥E (Control+Option+E): 한글 → 영문 (`ㅗ디ㅣㅐ` → `hello`)
3. 선택한 글자가 바로 바뀐다. 앱이 ⌘C·⌘V를 대신 누르고, 복사해 두었던 클립보드 내용은 되돌려 놓는다. 되돌리기는 그 앱의 ⌘Z.

- **터미널**(Terminal·iTerm2·Warp·Ghostty 등)은 붙여넣기가 선택을 바꾸지 않으므로, 바꾼 결과를 클립보드에만 넣는다 → ⌃U로 입력 줄을 지우고 ⌘V. 원래 클립보드는 메뉴의 "직전 클립보드 복구"로 되살린다.
- VS Code 등 일부 편집기는 선택 없이 ⌘C를 누르면 줄 전체를 복사하므로, 선택 없이 단축키를 누르면 그 줄이 바뀔 수 있다.

**복사한 내용만 변환** (설정 → 한영 변환 → 단축키 동작에서 선택): 직접 ⌘C → 단축키 → ⌘V. 권한이 필요 없다.

- 숫자·기호·공백·개행·이모지와 반대 언어 글자는 그대로 둔다. 문장 전체를 변환하면 정상 영어 단어도 바뀌므로 잘못된 부분만 복사한다.
- 대문자는 Shift·Caps Lock을 구분하지 않는다. R·E·Q·T·W·O·P는 쌍자음·ㅒ·ㅖ, 나머지 대문자는 소문자와 같다.
- 결과는 평문으로 저장한다(서식 없음). **직전 클립보드 복구**로 변환 전 내용(서식 포함)을 되살릴 수 있다. 새로 복사하거나 5분이 지나거나 화면을 잠그면 복구할 수 없다.
- 단축키는 설정 → 한영 변환에서 바꾸거나 해제할 수 있다. 등록에 실패해도 메뉴로는 계속 쓸 수 있다. 별도 권한이 필요 없다.
- "변환 후 입력 언어 맞추기"를 켜면 변환 성공 후 결과 언어의 입력기(설치된 것 중 선택)로 바꾼다. 이미 그 입력기면 그대로 둔다.
- 원문·결과·클립보드 내용은 디스크·로그에 남기지 않는다.

## 창 포커스 이동

여러 모니터에 놓인 창 사이를 키보드로 옮겨 다닌다. 앱이 아니라 창 단위라서 같은 Chrome의 다른 창도 각각 이동한다. 창 위치·크기는 바꾸지 않고 포인터도 움직이지 않는다.

| 단축키 (기본) | 동작 |
| --- | --- |
| ⌃⌥← (Control+Option+←) | 현재 창의 왼쪽 창 |
| ⌃⌥→ | 오른쪽 창 |
| ⌃⌥↑ | 위쪽 창 |
| ⌃⌥↓ | 아래쪽 창 |

- 방향은 모니터 이름이 아니라 실제 창 좌표로 정한다. 같은 높이(좌우 이동 기준)로 겹치는 창을 먼저, 그다음 가까운 창을 고른다. 화면 끝에서 반대편으로 돌아가지 않는다.
- 최소화·숨김·다른 데스크탑·완전히 가려진 창, 대화상자가 떠 있는 앱의 창은 건너뛴다. 같은 앱에 위치·크기가 똑같은 창이 여럿이면(최대화한 창 등) 앞에서 뒤 순서로 구분한다.
- **마우스 포인터 따라가기**(설정, 기본 끔): 키보드 포커스가 다른 모니터의 창으로 넘어가면 포인터를 그 창 가운데로 옮긴다(클릭은 하지 않음).
  - "창 포커스 이동으로 다른 모니터에 갈 때": ⌃⌥방향키로 옮겼을 때만. 같은 모니터 안의 이동에서는 그대로 둔다.
  - "포커스가 다른 모니터로 바뀔 때마다": Spotlight·⌘Tab·Dock·⌘` 등 어떤 방법이든. 데스크탑(Space)이 바뀐 뒤 0.8초 동안은 따라가지 않는다(데스크탑을 넘기면 macOS가 다른 모니터의 앱을 앞으로 가져와 포인터가 튀던 문제). 포인터가 이미 그 모니터에 있으면 그대로 둔다. 알림 등으로 다른 앱이 스스로 앞에 나와도 따라간다.
- 길게 눌러도 한 번만 이동한다. 빠르게 여러 번 누르면 최대 4번까지 순서대로, 매번 바뀐 포커스 기준으로 이동한다.
- 손쉬운 사용 권한이 필요하다(데스크탑 전환과 같은 권한). 화면 기록 권한은 쓰지 않는다.
- ⌃⌥ 조합은 VoiceOver 키와 겹치므로 VoiceOver를 쓰면 설정 → 창 포커스 이동에서 다른 조합으로 바꾼다.

### 창 목록 전환기

⌘Tab처럼 창 단위로, 지금 모니터의 창만 고른다. 겹쳐서 가려진 창을 앞으로 가져올 때 쓴다.

| 입력 (기본 ⌥`) | 동작 |
| --- | --- |
| ⌥를 누른 채 ` | 지금 모니터의 창 목록(앱 아이콘·앱 이름·창 제목)이 뜨고 바로 뒤 창이 선택된다 |
| (⌥를 누른 채) ` / ⇧` / 방향키 | 다음 / 이전 창 |
| ⌥를 뗌 또는 ↩ | 선택한 창을 앞으로 |
| Esc | 취소 |

- 목록은 앞에서 뒤 순서이고, 다른 창에 완전히 가려진 창도 나온다. 최소화·숨김·다른 데스크탑의 창과 대화상자가 떠 있는 앱은 빠진다.
- 빠르게 ⌥`를 눌렀다 떼면 패널 없이 바로 직전 창으로 간다.
- 보조키를 떼는 순간을 알아야 해서 이벤트 탭을 쓴다(입력 모니터링 권한). 창 제목은 목록 표시에만 쓰고 기록하지 않는다.
- "⌥⇥를 누른 채일 때만 열기"를 켜면 ⌥ + Tab을 누르고 있는 동안에만 `로 목록이 열리고, Tab 없이 누른 ⌥`는 앱으로 간다(키보드 포인터의 함께 누르고 있을 키가 Tab일 때).
- 단축키는 설정 → 창 포커스 이동 → "창 목록 전환기"에서 바꾼다. ⌥⇥는 키보드 포인터가 쓰므로 기본값에서 뺐다.

### 겹친 창 넘기기

| 입력 | 동작 |
| --- | --- |
| ⌃⌥] | 뒤로: 지금 창 밑에 깔린 창을 앞으로 (지금 창은 한 칸 뒤로) |
| ⌃⌥[ | 앞으로: 넘기던 순서에서 직전 창으로 |

- 지금 창의 모니터에서, 지금 창과 겹친 창을 먼저 그다음 나머지 창을 앞에서 뒤 순서로 돌고 끝에서 처음으로 돌아온다. 완전히 가려진 창도 포함한다.
- 1.5초 안에 이어 누르면 처음에 만든 순서를 그대로 쓴다(앞으로 가져오면 겹침 순서가 바뀌어, 매번 새로 세면 맨 앞 두 창만 오가기 때문). 오래 쉬거나 다른 앱·창으로 옮기면 새로 시작한다.
- macOS는 창을 맨 뒤로 내리는 공개 API가 없어 "뒤로"는 밑의 창을 앞으로 가져오는 방식이다.

### 창을 다른 모니터로 보내기

| 입력 | 동작 |
| --- | --- |
| ⌃⌥⌘← / → / ↑ / ↓ | 포커스된 창을 그 방향의 모니터로 |

- 보낼 모니터: 지금 창이 가장 많이 걸친 모니터에서, 그 방향으로 가운데가 넘어간 모니터 중 옆으로(수직 방향) 겹치는 모니터를 먼저, 그다음 진행 방향 간격·옆 방향 가운데 거리가 가까운 모니터 (WindowMovePlanner).
- 위치·크기: 메뉴 막대·Dock을 뺀 보이는 영역 기준, 축(가로·세로)마다 따로 정한다. 정렬 배치된 축(가장자리 8pt 이내에 붙어 있고 길이가 화면의 1/3·1/2·2/3·전부 ±3%)은 상대 위치·비율 그대로 늘리거나 줄이고(절반·꽉 채움 유지, 가장자리에 우연히 닿은 보통 창은 해당 없음), 떠 있는 축은 크기를 그대로 두고 창 가운데를 같은 비율 자리로 옮긴다(모니터 모양이 달라도 찌그러지지 않게). 어느 쪽이든 새 모니터 안으로 맞춘다. AXEnhancedUserInterface가 켜진 앱(Chrome 등)은 옮기는 동안만 끄고 되돌린다(켜져 있으면 크기 변경에 애니메이션이 끼어 어긋난다). AX로 크기 → 위치 → 크기 순서로 바꾼다(macOS가 크기를 지금 있는 모니터 안으로 제한해, 작은 모니터에서 큰 모니터로 갈 때 옮기기 전에 키우면 잘린다). Chrome처럼 위치를 늦게 반영하는 앱은 결과가 계획과 다르면 50ms 뒤 최대 3번 다시 맞춘다. 크기를 바꿀 수 없으면 위치만.
- 전체 화면(AXFullScreen) 창, 그 방향에 모니터 없음, 위치 바꾸기 거부는 짧은 안내로 알린다. 진단 기록에는 방향·앱 번들 ID·결과·걸린 시간만 남긴다.
- 키보드 포인터는 이 단축키를 WheelSpace 자체 단축키로 보고 앱 단축키 처리(잠깐 해제)를 하지 않는다.

### 새 데스크탑 만들기·창을 옆 데스크탑으로 보내기

| 입력 | 동작 |
| --- | --- |
| ⌃⌥⌘] | 포커스된 창(없으면 포인터)이 있는 모니터에 새 데스크탑 만들기 (맨 끝, 화면은 그대로) |
| ⌃⌥⇧[ / ⌃⌥⇧] | 포커스된 창을 같은 모니터의 왼쪽 / 오른쪽 데스크탑으로 (화면도 함께) |

- 처음 기본값 ⌃⌥⇧← / →를 그대로 쓰던 저장값은 ⌃⌥⇧[ / ]로 옮긴다(데스크탑 단축키를 [ ]로 모음).
- 화면만 넘기기는 macOS 기본 ⌃← / ⌃→로 충분해 따로 두지 않는다.
- 데스크탑 목록: 읽기 전용 비공개 함수 SLSCopyManagedDisplaySpaces(CGS 이름도 시도)를 dlsym으로 찾아, 그 모니터의 공간 ID·종류·지금 순서를 읽는다(전체 화면 앱 공간도 ⌃←/⌃→가 거쳐 가므로 순서에 포함, 그쪽으로는 옮기지 않는다).
- 창 옮기기: 비공개 SkyLight 연산 SLSBridgedMoveWindowsToManagedSpaceOperation(`initWithWindows:spaceID:` → `performWithWMBridgeDelegate`)으로 창 번호를 옆 공간 ID로 보낸다. 실행 중에 찾고, 없으면 "이 macOS에서는 옮길 수 없어요". 비동기라 SLSCopySpacesForWindows(마스크 0x7, 창 번호는 SInt32 CFNumber)로 창의 공간이 목표 하나가 될 때까지 최대 1.5초 확인한다(notMoved). 그다음 ⌃← / ⌃→로 화면을 넘기고 순서가 목표가 됐는지 확인(notSwitched)한 뒤 창을 AXRaise·앱 활성화한다.
  - 예전 함수 CGSMoveWindowsToManagedSpace는 macOS 14.5+에서 SIP 없이 막혔지만 bridged 연산은 SIP를 켠 채 동작한다(macOS 26.3.2 실측, 앱에 AppKit이 올라와 있어야 한다는 보고). 비공개라 macOS 업데이트로 사라질 수 있다.
  - 합성 마우스로 하던 이전 방식은 모두 실패했다: 제목 줄을 누른 채 ⌃← / ⌃→(데스크탑만 넘어감 — 마우스 버튼이 눌려 있는 동안 Dock이 합성 넘김 입력을 무시한다는 보고), 제목 줄을 누른 채 Mission Control 열기(잡은 게 풀림), Mission Control에서 창 썸네일 끌기(데스크탑 막대가 펼쳐지지 않음).
- 데스크탑 만들기(창을 들고 갈 때 오른쪽 끝이면, 설정 기본 켬): Mission Control을 열고 Dock AX 트리에서 그 모니터의 "데스크탑 추가" 버튼(식별자 mc.spaces.add, 또는 설명에 add desktop·데스크탑 추가)을 AXPress, Esc로 닫는다. 버튼은 숨어 있어 자기 모니터 오른쪽 바깥(+24pt)에 있다고 알려 주므로, 버튼 위치가 아니라 위쪽 "mc.display" 묶음의 영역으로 모니터를 짝짓는다. 누른 뒤 그 모니터의 데스크탑 수가 늘었는지 확인하고, 아니면 창을 옮기지 않는다. 새 데스크탑은 맨 끝에 생기므로 오른쪽 끝에서만 만들고, 왼쪽 끝은 "맨 앞에는 만들 수 없어요".
- 진단 기록에는 방향·앱 번들 ID·결과·걸린 시간·데스크탑 순서만 남긴다.

## 키보드 포인터

특수키를 누른 채 방향키로 마우스 포인터를 움직이고 클릭·드래그·스크롤한다. 특수키를 놓으면 방향키는 평소대로 동작한다. **기본값은 꺼짐** — 설정 → 키보드 포인터에서 켠다.

| 입력 (기본 ⌥⇥, Option + Tab) | 동작 |
| --- | --- |
| ⌥ + Tab을 누른 채 ←→↑↓ | 포인터 이동 (두 키를 함께 누르면 대각선) |
| ⌥⇧ + Tab을 누른 채 ←→↑↓ | 빠르게 이동 (가속 없이 바로) |
| ⌥⌘ + Tab을 누른 채 ←→↑↓ | 세로·가로 스크롤 |
| ⌥ + Tab을 누른 채 ↩ | 왼쪽 클릭 |
| ⌥ + Tab을 누른 채 R | 오른쪽 클릭 |
| ⌥ + Tab을 누른 채 D | 더블클릭 |
| ⌥ + Tab을 누른 채 G를 누르고 있기 | 누르고 있는 동안 드래그 (방향키로 이동, G를 떼면 놓기) |
| Esc | 드래그 취소 |

- 기본 조합의 스크롤 키는 ⌘, 빠르게 키는 ⇧다. ⌃로 두면 ⌃⌥ + 방향키가 창 포커스 이동 기본 단축키와 겹쳐, 전역 단축키가 먼저 실행되고 스크롤이 동작하지 않는다. 설정 화면은 창 포커스 이동·한영 변환 단축키와 겹치는 조합을 경고한다.
- 가속: 방향키를 누르는 순간 설정 속도의 15%로 시작해 0.5초 동안 설정 속도까지 빨라진다(이동·스크롤 공통). 짧게 누르면 조금만 움직여 세밀하게 맞출 수 있다. 빠르게 키(⇧)를 누른 동안은 가속 없이 바로 빠른 속도다. "기본을 빠르게" 옵션을 켜면 반대로 평소가 빠른 속도이고, 빠르게 키를 누르는 동안 가속이 적용된 느린 속도가 된다(세밀 조절). 가속 시간(0이면 끔)과 시작 속도는 설정에서 바꾼다.
- 느리게 키(기본 A, 없앨 수 있음): ⌥⇥ + A + 방향키(포인터 모드에서는 A + 방향키)를 누른 동안 가속 없이 일정한 느린 속도(기본 설정 속도의 0.3배, 0.1~0.7배)로 이동·스크롤한다. 빠르게 키와 함께 누르면 느리게가 우선이다. 일반 키 느리게 키는 누르고 있는 키(Tab)가 있는 조합에서만 쓰고, 누르고 있는 키가 없는 프리셋을 고르면 빠진다.
- 단축키는 설정 → 키보드 포인터 → "단축키 설정"에서 바꾼다. 프리셋(⌥⇥ 기본 / ⌃⇧ / ⌃⌘ / ⌃⌥ / ⌥⌘)을 고르거나, 필수 보조키(⌃⌥⇧⌘ 자유 조합)·함께 누르고 있을 키(없음 또는 아무 키)·스크롤 키·빠르게 키·클릭/오른쪽 클릭/더블클릭/드래그 키를 하나씩 정한다. 편집 내용은 "적용"을 눌러야 반영된다.
- 스크롤 키·빠르게 키·느리게 키는 보조키 하나(⌃⌥⇧⌘) 또는 일반 키(예: S)로 고른다. 일반 키는 Tab처럼 조합(⌥ + Tab)을 누르고 있을 때만 가로채고, 그 키를 누르고 있는 동안만 스크롤·빠르게가 된다. 평소의 그 키 입력에는 영향이 없다.
- 적용할 수 없는 구성(필수 보조키 없음, 스크롤·빠르게 키가 필수 보조키와 겹침, 방향키·Esc 지정, 같은 키 중복)은 적용 버튼이 꺼지고, 저장값이 그런 구성이면 기본 단축키로 되돌린다. ⌃ 하나만 필수 보조키로 쓰거나, 누르고 있을 키 없이 ⇧·⌥ 하나만 쓰면 경고를 보여준다.
- Tab은 보조키가 아니라 일반 키라서, ⌥와 함께 누르는 순간 앱에 보내지 않고 잡아 둔다. 방향키·동작 키를 쓰지 않고 떼면 원래 ⌥Tab(⌥⇧Tab)을 앱에 다시 보낸다. 누를 때가 아니라 뗄 때 반응한다.
- Tab 없이 누른 ⌥ + 방향키(단어 단위 이동)는 가로채지 않는다.
- ⌃Tab은 쓸 수 없다. Tab은 방향키 이벤트에 표시되지 않아 ⌃→가 그대로 시스템 단축키(데스크탑 이동·미션 컨트롤)로 처리되고, 이벤트 탭에서 소비해도 시스템이 따로 실행한다.
- 포인터 모드(vi의 일반 모드처럼): ⌥를 누른 채 Tab을 빠르게 두 번 누르면 켜진다. 켜져 있는 동안 ⌥ + Tab 없이 방향키·↩·R·D·G·스크롤 키(⌘)·빠르게 키(⇧)·느리게 키(A)로 조작한다. 그 밖의 글자·숫자·Space·Tab은 앱에 입력되지 않고(vi 일반 모드처럼), I를 누르면 평소 입력 모드로 돌아간다. ⌘·⌃ 단축키, Esc, 🌐/Fn, 기능 키(F1~), Fn + 방향키(Home·End·Page Up·Page Down)는 그대로 앱에 전달된다. 메뉴나 설정 창을 열면 꺼진다. "키보드로 클릭하면 포인터 모드 해제"(기본 꺼짐)를 켜면 클릭·더블클릭·드래그 놓기 뒤 바로 평소 입력으로 돌아간다. 켜져 있는 동안 모든 모니터 위쪽에 "포인터 모드" 토스트가 계속 떠 있고 메뉴 막대 아이콘이 바뀐다. 꺼지면 토스트가 "포인터 모드 해제"로 바뀌었다가 사라진다.
- 왼손 모드: ⌥⇧⇥ 두 번(⌥⇥ 두 번에 ⇧를 더해)으로 켜고 끈다. 일반 포인터 모드에서 ⌥⇧⇥ 두 번을 누르면 끄지 않고 왼손 모드로 바뀌고, 포인터 모드에서 Q를 누르면 일반 ↔ 왼손 모드를 오간다(Q를 다른 포인터 키로 지정했으면 동작하지 않는다). 한 손으로 방향과 동작을 함께 다루도록 단순하게 짰다: W·A·S·D 이동, R·F·E·T 위·아래·왼쪽·오른쪽 스크롤(R을 가운데 둔 십자), Space 클릭(두 번 = 더블클릭), C 오른쪽 클릭, V 드래그 시작·놓기(토글, Esc도 놓기), 빠르게 키(⇧)를 누른 채 빠르게. 누른 채 쓰는 키는 빠르게 키뿐이고, 이동과 스크롤은 하나를 누르는 동안 다른 쪽을 무시한다. 드래그 중에는 토스트가 "드래그 중 · V로 놓기"로 바뀐다. 방향키·↩도 함께 동작하고, ⌥⇥ 두 번으로 켠 일반 포인터 모드와 ⌥⇥를 누른 채 쓰는 방식은 기존 키 그대로다. 앱 단축키로 잠깐 해제됐다 돌아오면 왼손 모드도 그대로 이어진다. ⌘·⌃·⌥가 섞인 입력(⌘S, ⌥Space 등)은 왼손 배치로 보지 않는다.
- 포인터 모드에서 ⌘·⌃ 앱 단축키(⌘B 등)를 누르면 단축키는 앱에 그대로 가고, 기본은 "보조키를 누르는 동안만 해제"다. ⌘·⌃를 누르고 있는 동안은 이어서 쓰는 단축키·키가 모두 앱으로 가고, 떼면 바로 포인터 모드로 돌아온다. ⌘·⌃를 쥔 채 누른 방향키·↩·Esc는 ⌘·⌃를 빼고 보내므로, ⌘B로 연 목록을 ⌘를 떼지 않고 ↓↓↩로 고를 수 있다(이때 ⌘↓ 같은 원래 단축키는 ⌘를 한 번 뗐다 눌러야 한다. 설정의 "⌘ 없이 보내기"를 끄면 원래 단축키로 간다). ⌘를 쥔 채 ⇧만 눌렀다 떼면 포인터 모드가 완전히 꺼져, ⌘를 떼도 돌아오지 않는다(목록·입력창을 평소 키보드로 쓸 때). "잠깐 해제 후 돌아오기"를 고르면 단축키 뒤 0.7초 동안 아무 키도 누르지 않으면(바로 이동하는 단축키) 다시 포인터 모드가 되고, 방향키·글자로 팝업·목록·검색창을 쓰다가 ↩·Esc를 누르면 그 키를 앱에 보낸 뒤 다시 포인터 모드가 된다. 앱 단축키 뒤 포인터 모드로 돌아오면 포인터를 포커스된 곳(글자 커서 옆, 커서가 없으면 포커스된 항목 가운데)으로 옮긴다(설정, 기본 켬). 손쉬운 사용 API의 선택 범위 위치(AXBoundsForRange)를 쓰고, 앱이 알려 주지 않거나 요소가 화면의 절반보다 크면 옮기지 않는다. 포인터 모드를 켤 때도 옮기는 옵션(기본 끔)이 있다. 잠깐 해제 동안 메뉴 막대 아이콘은 그대로이고 토스트가 "포인터 모드 잠깐 해제"로 바뀐다. 설정에서 "포인터 모드 해제"(완전히)·"아무것도 안 함"으로 바꿀 수 있고, 유지할 단축키(기본 ⌘C·⌘V·⌘X·⌘Z·⌘⇧Z·⌘A·⌘Tab)는 포인터 모드를 유지한다. ⌘↑ 같은 방향키 단축키도 앱 단축키로 다루고, 스크롤·느리게 키로 정한 보조키 + 방향키만 포인터가 쓴다.
- 포인터 모드 자동 해제: 해제 단축키 목록(기본 ⌘Space·⌥Space, 설정에서 추가·삭제)을 누르면 포인터 모드가 꺼지고 단축키는 그대로 동작한다. 이 단축키들은 시스템·다른 앱의 전역 단축키라 세션 단계 탭보다 먼저 처리되므로, HID 단계 듣기 전용 탭으로 따로 감시한다. 또 포인터 모드에서 클릭(키보드·실제 마우스)한 곳의 포커스가 글자 입력란이면 포인터 모드가 꺼진다(손쉬운 사용 API로 확인, 설정에서 끌 수 있다). 콤보 상자(글자를 칠 수 있는 선택 목록 포함)와 값을 바꿀 수 없는 영역(비활성 입력란 등)은 입력란으로 보지 않아 포인터 모드가 유지된다. 앱이 읽기 전용 여부를 알려 주지 않는 영역은 "해제하지 않을 영역" 규칙으로 뺀다. 규칙은 앱(비우면 모든 브라우저)·역할·웹 페이지의 scheme·호스트·DOM 클래스(내용·제목은 보지 않는다)로 맞추고, 기본 규칙은 개발자 도구 코드 편집기(devtools 페이지의 cm-content — Response·Preview·Console 입력 줄) 하나다. 원치 않는 곳에서 풀렸을 때 메뉴 막대의 "방금 해제 취소하고 이 영역 제외"·"…모든 브라우저에서 제외"로 규칙을 만든다. 규칙은 설정에서 보고 뺄 수 있다. 입력란을 클릭해도 포인터 모드를 유지할 앱은 설정의 "해제하지 않을 앱"에 넣는다(번들 ID로 저장). Chrome·Electron 같은 Chromium 계열 앱은 요청하기 전까지 웹 페이지 내용의 손쉬운 사용 정보를 만들지 않아, 처음 확인할 때 그 앱에 AXManualAccessibility를 켜 달라고 요청한다(Electron 계열). Chrome은 이 요청을 지원하지 않아 포커스 정보가 비어 있으면 그 앱에만 한 번 AXEnhancedUserInterface(VoiceOver가 쓰는 요청)를 켠다. 그 앱의 메모리·CPU 사용이 조금 늘고, 다른 창 정리 앱이 그 앱 창 크기를 바꿀 때 애니메이션이 생길 수 있다.
- 포인터 모드 켜는 방법(⌥Tab 두 번 / 단축키 / 사용 안 함)과 입력 모드로 돌아가는 키는 설정에서 바꾼다. ⌥Tab 두 번을 쓰는 동안 ⌥Tab 한 번은 두 번째 누름을 기다렸다가(0.35초) 앱에 전달된다.
- 왼쪽 클릭이 Space가 아니라 Return인 이유: ⌃⌘Space는 macOS의 이모지·기호 창 단축키다.
- 이동 속도(기본 650pt/초)·빠른 배율·스크롤 속도는 키보드 이동에만 적용된다. macOS의 마우스·트랙패드 속도 설정은 읽거나 바꾸지 않는다.
- 드래그 키(또는 왼손 모드 V)를 눌러도 버튼은 첫 이동 때 누른다. 누르는 순간 누르면 움직이지 않고 뗐을 때 클릭이 되어 버리기 때문이다.
- 화면 사이 빈 공간은 건너뛰지 않고, 맞닿은 경계에서만 다른 모니터로 넘어간다. 모서리에서는 갈 수 있는 쪽으로 미끄러진다.
- 특수키를 놓거나, 메뉴·설정 창을 열거나, 화면을 잠그면 이동과 드래그가 바로 멈추고 앱이 누른 버튼을 놓는다.
- 입력 모니터링과 손쉬운 사용 권한이 필요하다(데스크탑 전환과 같은 권한).

## 실행 중인 앱 선택

실행 중인 앱을 키보드로 골라 그 앱의 창을 확실히 보여 준다. 숨긴 앱(⌘H), 최소화된 창만 있는 앱, ⌘W로 창을 모두 닫은 앱도 고를 수 있다.

| 입력 (기본 ⌃⌥⇥) | 동작 |
| --- | --- |
| ⌃⌥⇥ 또는 메뉴 "실행 중인 앱 선택…" | 앱 목록(최근 사용 순, 처음엔 직전 앱 선택) |
| 타이핑 / ↑↓ | 이름·번들 ID 검색 / 고르기 |
| Return | 그 앱의 창 보이기 |
| Esc | 취소하고 원래 앱으로 |

선택한 뒤에는 숨김 해제 → 다시 조회 → 기존 창(모달 우선) → 최소화된 창 하나 복원 → 창이 없음이 확인될 때만 다시 열기 요청(Dock 아이콘 클릭과 같은 요청, 한 번만, 2초 안에 창이 생기는지 확인) 순서로 처리한다.

- 창 상태를 확인하지 못하면(권한·응답 없음) "창 없음"으로 보지 않고 앱만 앞으로 가져온다.
- 화면에 창이 없으면(다른 데스크탑의 창인지, Teams처럼 닫혀 숨긴 창인지 창 목록으로는 구별되지 않는다) Dock 클릭과 같은 다시 열기를 보낸다. 창이 다른 데스크탑에 있으면 macOS가 그리로 옮기고 앱은 새 창을 만들지 않는다. 다시 열기를 끄면 다른 데스크탑을 확인하라고 안내만 한다.
- ⌘N을 보내거나 메뉴를 임의로 실행하지 않는다. 닫은 문서·탭은 복구하지 않는다.
- 선택 직후 종료된 앱은 다시 실행하지 않는다. 다만 다시 열기 요청과 앱 종료가 거의 동시에 일어나면 앱이 새로 실행될 수 있다(공개 API의 한계).
- 목록에는 Dock에 나오는 앱만 나온다. Docker Desktop처럼 창을 닫으면 메뉴 막대 앱으로 바뀌는 앱은 설정의 "목록에 함께 보일 앱"에 넣으면 나오고, 고르면 다시 열기 요청으로 창을 연다.
- 검색란 입력을 받으려고 목록이 열린 동안 WheelSpace가 잠깐 전면 앱이 된다. 최근 사용 순서는 메모리에만 있다.

- macOS 13 이상 (개발·확인 환경: macOS 26.3, Apple Silicon)
- Xcode Command Line Tools (Swift 5.10 이상)
- 데스크탑 2개 이상
- 시스템 설정 → 키보드 → 키보드 단축키 → Mission Control에서 "왼쪽 공간으로 이동(⌃←)"·"오른쪽 공간으로 이동(⌃→)"이 켜져 있어야 한다

## 처음 실행과 권한

1. 실행하면 메뉴 막대에 아이콘이 생기고, 권한이 없으면 설정 창이 열린다.
2. **권한 요청**을 누르고 시스템 설정에서 다음 두 항목에 WheelSpace를 허용한다.
   - 개인정보 보호 및 보안 → **입력 모니터링** (휠 감지)
   - 개인정보 보호 및 보안 → **손쉬운 사용** (단축키 전송)
3. 앱으로 돌아오면 자동으로 다시 확인한다. 반영되지 않으면 **앱 다시 실행**.
4. **이동 테스트**의 왼쪽/오른쪽 버튼으로 데스크탑이 실제로 바뀌는지 확인한다.
5. Option + 휠로 이동해 본다.

권한은 설치 경로의 앱에 부여된다. 항상 `~/Applications/WheelSpace.app`에서 실행한다.

### 권한 재설정

`scripts/build-app.sh`는 이 맥의 전용 키체인에 만든 고정 자체 서명 인증서로 서명해, 다시 빌드해도 권한이 유지된다. 그래도 권한이 동작하지 않으면 (목록에 WheelSpace가 켜져 있는데도 "필요"로 나오면):

1. 시스템 설정의 입력 모니터링·손쉬운 사용 목록에서 WheelSpace를 `−`로 제거
2. 앱을 다시 실행하고 권한을 다시 허용

터미널에서 한 번에 초기화: `tccutil reset ListenEvent com.bell.WheelSpace; tccutil reset Accessibility com.bell.WheelSpace`

## 메뉴와 설정

- 메뉴: [데스크탑 전환] 상태·사용 켜기·끄기 / [한영 변환] 영문→한글·한글→영문·직전 클립보드 복구 / 설정, 권한 및 동작 확인, 종료
- 설정 창은 왼쪽 사이드바로 기능을 고른다: **데스크탑 전환** · **한영 변환** · **일반**(로그인 시 실행, 전체 초기화, 진단 정보 복사)
- 설정: 보조키(Option/Control/Command/Shift), 전환에 쓸 휠(세로/좌우/둘 다), 방향 반전, 뒤로·앞으로 버튼(끔/보조키와 함께/보조키 없이), 전환 최소 간격(200~1,000ms, 기본 400ms — 버튼에도 적용), 휠 감도, 로그인 시 실행, 설정 초기화, 상태 진단 정보 복사
- 뒤로·앞으로 버튼을 "보조키 없이"로 두면 브라우저·Finder의 뒤로·앞으로 기능 대신 데스크탑을 이동한다
- 아이콘: 사용 중 `▥` / 일시정지 `⏸` / 권한 필요 `🔒` / 입력 감지 오류 `⚠`

진단 정보에는 앱·OS 버전, 권한 상태, 탭 오류 같은 상태 기록만 들어간다. 키 입력·스크롤 내용은 기록하지 않는다.

## 삭제

1. 메뉴에서 로그인 시 실행을 끈다
2. WheelSpace 종료
3. `~/Applications/WheelSpace.app` 삭제
4. (선택) 설정 삭제: `defaults delete com.bell.WheelSpace`
5. (선택) 권한 목록 정리: 위 `tccutil reset` 명령

## 알려진 제한

- 이동 단축키를 보낸 것까지만 확인한다. macOS가 실제로 이동했는지는 판단하지 않는다 (첫·마지막 데스크탑에서 더 이동하지 않는 것은 정상).
- Mission Control 이동 단축키를 끄거나 다른 키로 바꾸면 동작하지 않는다.
- 트랙패드·Magic Mouse를 일반 휠과 구분하지 않는다. 연속 입력은 누적 임계값으로 처리하며 일반 휠 마우스를 우선 지원한다.
- 다중 모니터에서는 macOS 기본 동작(마우스 포인터가 있는 디스플레이 기준)을 따른다.
- 다른 마우스 유틸리티가 같은 조합을 쓰면 두 번 이동하거나 충돌할 수 있다.
- 뒤로·앞으로 버튼은 표준 버튼 번호 3·4로 들어올 때만 인식한다. Logi Options+ 등 드라이버가 버튼을 키 입력으로 바꿔 보내면 인식하지 못하므로, 드라이버에서 해당 버튼을 기본 동작으로 둔다.
